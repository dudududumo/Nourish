# Nourish / 轻养

一个围绕身体数据、饮食计划与执行反馈构建的 AI 营养健康管理产品原型。

> 项目重点不是“让大模型替用户做健康决定”，而是探索如何把不稳定的模型输出放进可检查、可确认、可回退、可评测的产品流程。

## 核心问题

身体数据、冰箱库存和饮食计划往往分散在不同应用里。用户真正需要的不是又一个聊天框，而是一条能够持续执行的闭环：

1. 录入或识别身体数据；
2. 结合目标与库存生成饮食建议；
3. 用户检查并确认调整；
4. 在执行过程中记录反馈；
5. 用固定用例评测模型的安全边界和指令遵循。

## 产品模块

- **今日与周计划**：生成结构化七日食谱、采购清单和烹饪步骤。
- **AI 营养助手**：结合最新身体数据、计划和库存回答问题。
- **身体数据**：支持体脂秤截图解析，解析结果须经用户确认。
- **冰箱管理**：维护库存和临期信息，为计划提供上下文。
- **轻断食**：由确定性规则完成健康筛查和窗口建议，高风险情况硬拦截。
- **Nourish Eval Lab**：运行固定安全测试集，展示规则评分、逐条回答与人工复核结果。

## AI 产品设计取舍

| 场景 | 是否交给模型 | 产品约束 |
| --- | --- | --- |
| 体脂秤截图解析 | 是 | 只提取白名单字段；缺失项不得编造；结果由用户确认 |
| 食谱和自然语言建议 | 是 | 结构化输出、字段归一化、异常兜底、确认后应用 |
| 高风险断食筛查 | 否 | 使用确定性规则；孕哺期、进食障碍、低血糖、糖尿病、用药及年龄风险直接拦截 |
| 医学诊断与治疗 | 否 | 明确不替代医生；危险症状提示立即停止并及时就医 |
| 模型质量判断 | 模型 + 人 | 固定用例规则初筛，同时保留人工复核与原始回答 |

## 评测体系

首批评测集覆盖四个维度：

- 健康安全边界；
- 关键信息完整性；
- 过敏和用户约束遵循；
- 测量不确定性表达。

评测中心不预置虚构分数。用户配置模型后运行用例，系统记录真实通过率、关键词命中、风险表达和人工复核结论，并可导出 JSON 作为迭代证据。

当前评分仍是规则基线，不等同于医学正确性，也不能替代专家评审。后续重点是扩充对抗用例、建立人工 Rubric，并比较不同模型与提示词版本。

## 技术架构

- Next.js / React / Tailwind CSS
- Vinext + Cloudflare Workers
- Cloudflare D1 + Drizzle ORM
- BYOK 模型配置，兼容 OpenAI 风格 Chat Completions 接口
- Capacitor iOS 容器

## 安全设计

- 密码使用带随机盐的 PBKDF2-SHA256；旧账户登录后自动迁移。
- Session Cookie 启用 `HttpOnly`、`Secure` 和 `SameSite=Lax`。
- 用户 API Key 使用 AES-GCM 加密保存，生产环境必须配置服务端加密密钥。
- AI Endpoint 必须使用 HTTPS，并阻止本机和常见内网地址。
- 图片解析限制 MIME 类型和请求体大小。
- 健康建议强调不确定性、用户确认和高风险转介。

## 本地运行

项目要求 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

生产环境部署在 Cloudflare Workers，D1 数据库名默认为 `nourish`。已有数据库部署不会重复执行历史迁移；新数据库初始化时显式设置 `INITIALIZE_D1=1`。

## 项目状态

这是个人产品与工程实践项目，不是医疗器械或临床营养服务。所有 AI 输出仅作为信息参考，用户不应据此替代专业医疗建议。
